### Engineering, cloud and IT

All six departments use AI in the same way. An assistant drafts code, tests, infrastructure templates, runbooks or knowledge articles. A human then verifies the draft against something that can pass or fail: a test run, a plan or dry-run, or telemetry. Claude Code's own best-practice guidance says to give the agent a check it can run. Shared risks are source code and credentials pasted into prompts, hallucinated or insecure output, and agents acting with broad permissions on production systems or ERP. Departments 41-44 should train together on agentic coding, verification gates and secrets hygiene, and 43-45 together on cloud and ticket-system tooling. Department 46 should join 45 for ticket and knowledge workflows, and 46 should train with Finance on SAP data. Evidence quality is uneven. Most quantified claims come from vendors or from a single company's self-report, so managers should measure their own baselines. ServiceNow, Salesforce, Dynatrace and Cursor claims could not be verified because those pages could not be opened.

*Fact-check:* All cited URLs opened, and most specific claims matched their sources (Zoominfo figures, Accenture RCT design, Meta 73%, AWS, Google, Azure, Datadog, Security Copilot, SAP). Errors found were misattributions and extrapolations rather than fabrications. Remaining weaknesses are heavy reliance on vendor pages and a single source for department 46, so the low confidence there and in 42 and 45 stands. Cursor, ServiceNow, Salesforce, Dynatrace and GitHub Copilot for pipeline files were not checked against any opened page. 13 correction(s) or removal(s) were applied.

**41 Software Engineering - Applications** (Core; medium confidence)

- **AI use cases in practice:**
    - Inline code completion and chat in the IDE with GitHub Copilot. A Zoominfo rollout to more than 400 developers measured acceptance rates (33% of suggestions, 20% of lines of code) and satisfaction. [1]
    - Developers self-reported a median 20% reduction in task time, with 77% saying work quality improved. These are survey results, not measured output. [1]
    - A randomized controlled trial at Accenture used DevOps telemetry plus a survey and found high adoption and satisfaction. The 'up to 55% faster' figure comes from GitHub's earlier lab studies, which the same post cites, not from the Accenture trial. This is vendor-run research. [2]
    - Generating unit tests, debugging and documenting code in the IDE with Gemini Code Assist, which cites sources when it quotes at length. [3]
    - Agentic coding in the terminal or IDE with Claude Code, using checkpoints to rewind changes. Subagents and hooks are described as Agent SDK support for custom workflows. [4]
    - Code review support: Zoominfo flagged limits in domain-specific context and the need to vet generated code. [1]
- **Capstone deliverable:** Refactor or document one real module (non-production data) using an approved assistant. Deliver the merged pull request, a prompt log, the tests that gate it, a security review of the AI-generated diff, and a measured before-and-after time comparison against a similar manual task. Assessed against a rubric on correctness, test evidence and honest reporting of rework.
- **Data risks and rules:** Source code, credentials and API keys, proprietary algorithms and customer data in test fixtures. Rules: no secrets or production data in prompts; use enterprise-licensed tools with data-retention terms checked; review licence and citation flags on suggestions; treat generated code as untrusted until tested and scanned. Regulatory hooks (GDPR for personal data in fixtures) apply but were not covered by sources.
- **Adoption KPIs:** Weekly active users as a share of licences; suggestion acceptance rate; pull request cycle time against a pre-rollout baseline; developer satisfaction survey score; defect or revert rate on AI-assisted changes.
- **Curriculum emphasis:** Core tier, so most hours go to hands-on practice, then a short module on risk. Prioritise GitHub Copilot (the most evidence of enterprise rollout), Claude Code (agentic multi-file work with verification) and Gemini Code Assist (a Google Cloud shop). Spend a block on verification habits: run tests, review diffs, never accept blindly.
- **Tool-list fit:** Good fit overall. Gemini Code Assist's own documentation says new Standard and Enterprise subscriptions are no longer available for purchase, so confirm availability before teaching it. [3] Cursor is listed but no opened page covers it: not verified. ChatGPT Enterprise is a general assistant and is a weaker fit for IDE work than the others (not verified).

**42 Quality Engineering & Testing** (Advanced; low confidence)

- **AI use cases in practice:**
    - Generating Playwright tests from specs or user stories with Claude Code, Cursor or Copilot. A vendor blog article says generation works only with a mutation-score gate. [1]
    - Meta's mutation-guided test generation: engineers accepted 73% of LLM-generated tests (as reported in a secondary article citing a FSE 2025 paper). [1]
    - Triage agents that group CI failures, classify them as bug, flaky or environment, and write an investigation brief. The same article rates triage as the best return today. [1]
    - Maintenance agents that patch broken selectors; the article says these need a human-approval gate. [1]
    - Unit test generation in the IDE with Gemini Code Assist. [2]
    - Playwright 1.59 agent-oriented features (Screencast video receipts, browser.bind(), CLI debugger for agents). [1]
- **Capstone deliverable:** Take one feature with a user story. Generate a Playwright test set with an AI assistant, gate it with mutation or seeded-defect checks, and triage 10 real or sample CI failures with the assistant. Deliver the suite, the documented prompts, a false-positive and miss rate for the triage, and hours saved.
- **Data risks and rules:** Test data may contain personal data (GDPR), payment card data (PCI DSS) or production snapshots; defect tickets may include credentials or customer details. Rules: synthetic or masked data only; no production logs pasted into public tools; AI-written tests need human review so they do not freeze existing bugs in place.
- **Adoption KPIs:** Share of tests AI-drafted and accepted; flaky-test triage time; mutation score or defect-escape rate of AI-generated tests; CI failure mean time to classify; maintenance hours per sprint.
- **Curriculum emphasis:** Advanced tier: most hours on workflow patterns, with practice on real suites. Prioritise Claude Code and GitHub Copilot for generation and Playwright as the target framework. Teach the four-category split (generation, maintenance, triage, exploration) and when to apply human gates.
- **Tool-list fit:** Playwright is a framework, not an AI tool, and needs framing as the target of AI generation. ChatGPT Enterprise fit for pipeline work: not verified. The handbook omits dedicated test-triage platforms: the source article names TestDino and Sentry AI, but it is published by TestDino, a vendor, so treat as indicative. Include the prompt log, a list of assistant errors found, and time saved.
- **Data risks and rules:** Cloud credentials, account IDs, network topology, IAM policies, and logs that can contain customer data (GDPR, HIPAA, PCI DSS). Rules: least-privilege access for any assistant, since the assistants act with the user's permissions [3]; human approval before apply; no secrets in prompts; verify recommendations against billing before acting.
- **Adoption KPIs:** Cost savings realised from AI recommendations, verified; time to draft a reviewed IaC change; proportion of AI-generated IaC passing policy checks first time; troubleshooting time for common incidents; number of assistant-caused misconfigurations.
- **Curriculum emphasis:** Specialist tier: depth on tools matching your cloud provider. **44 DevOps & Site Reliability Engineering** (Specialist; medium confidence)

- **AI use cases in practice:**
    - Autonomous alert investigation: Datadog Bits AI SRE analyses runbooks and telemetry, forms hypothetical root causes, validates its findings and delivers a conclusion to collaboration tools before on-call staff log in (vendor claim: hours to minutes). [1]
    - At Nulab, a small SRE team uses Bits Investigation across logs, metrics and traces; many low-priority alerts that took at least 30 minutes can now be triaged in under 5 minutes. This is a vendor-published case study. [2]
    - Natural-language investigation across infrastructure and costs, replacing hand-written queries. [2]
    - Verification loops in Claude Code: running a check the agent can read, such as a test or build. Applying this to runbook and pipeline scripts is this handbook's extrapolation. [3]
    - Runbook drafting by a general assistant (not verified in the sources); Bits posts its conclusion in collaboration tools. [1]
- **Capstone deliverable:** Using a past incident (sanitised), have an AI assistant draft a runbook and an investigation timeline. Compare its root-cause hypothesis with the actual post-mortem, and deliver the runbook, the prompt log, an accuracy assessment (hits, misses, unsupported claims) and time saved.
- **Data risks and rules:** Logs and traces can contain personal data (GDPR), health data (HIPAA) and credentials; incident records may contain security-sensitive detail. Rules: redact before sharing outside the observability platform; use role-based access (Datadog advertises RBAC and HIPAA-regulated workload support for Bits AI SRE [1]); AI conclusions are hypotheses requiring human confirmation before changes to production.
- **Adoption KPIs:** Mean time to acknowledge and to resolve; share of alerts with an AI investigation accepted as correct; false-hypothesis rate; runbook coverage of top alert types; on-call hours saved.
- **Curriculum emphasis:** Specialist tier: hours on incident-style simulations. Prioritise the observability-native agent (Datadog Bits AI) and Claude Code for runbooks and scripts, plus GitHub Copilot for pipeline files (not verified). Train on confirming AI root causes rather than trusting them.
- **Tool-list fit:** Datadog and Dynatrace are each relevant only if the company uses them; teach the one in use. Dynatrace Davis AI could not be verified from an opened page. Gemini Code Assist as a weaker fit for incident work is the author's judgement (not verified); check its new-subscription availability. Evidence is mostly vendor-published.

- **AI use cases in practice:**

- **Data risks and rules:** Financial records and SOX-relevant controls, supplier and employee master data (GDPR), customer data in CRM. - **Adoption KPIs:** Joule or assistant monthly active users; time to resolve application support requests; change-request cycle time; error or rework rate on AI-assisted transactions; audit findings related to AI-assisted actions.
- **Curriculum emphasis:** Specialist tier: most hours on the platform in use. Prioritise SAP Joule (or Salesforce Einstein for CRM-led teams, not verified), Claude for code and documentation, and Microsoft 365 Copilot for functional documents (not verified for ERP). Teach authorisation scoping and test evidence before any transactional use.
- **Tool-list fit:** SAP Joule fits SAP shops only; Salesforce Einstein fits CRM teams only and is not verified.
