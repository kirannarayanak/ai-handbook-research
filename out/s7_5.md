### Engineering, cloud and IT

All six departments use AI in the same way. An assistant drafts code, tests, infrastructure templates, runbooks or knowledge articles. A human then verifies the draft against something that can pass or fail: a test run, a plan or dry-run, or telemetry. Claude Code's own best-practice guidance says to give the agent a check it can run. Shared risks are source code and credentials pasted into prompts, hallucinated or insecure output, and agents acting with broad permissions on production systems or ERP. Departments 41-44 should train together on agentic coding, verification gates and secrets hygiene, and 43-45 together on cloud and ticket-system tooling. Department 46 should join 45 for ticket and knowledge workflows, and 46 should train with Finance on SAP data. Evidence quality is uneven. Most quantified claims come from vendors or from a single company's self-report, so managers should measure their own baselines. ServiceNow, Salesforce, Dynatrace and Cursor claims could not be verified because those pages could not be opened.

*Fact-check:* All cited URLs opened, and most specific claims matched their sources (Zoominfo figures, Accenture RCT design, Meta 73%, AWS, Google, Azure, Datadog, Security Copilot, SAP). Errors found were misattributions and extrapolations rather than fabrications. Remaining weaknesses are heavy reliance on vendor pages and a single source for department 46, so the low confidence there and in 42 and 45 stands. Cursor, ServiceNow, Salesforce, Dynatrace and GitHub Copilot for pipeline files were not checked against any opened page. Re-research of departments 42, 45, 46 (second pass): All seven cited pages opened and supported the main statistics (WQR 19%, 67%, 60%, test-design lead; Gartner 69%; Joule 60% and 40% figures; the ITSM 72-hour definition and the 54% ServiceNow figure). The corrections were the removal of one unsupported claim, a few tightened wordings, and not-verified labels on tool names the sources do not cover. Evidence is mostly vendor-adjacent or opinion pieces (OpenText co-publishes the WQR, the ITSM author runs a competitor, ERP Today is promotional), so confidence stays medium, medium and low. 22 correction(s) or removal(s) were applied.

**41 Software Engineering - Applications** (Core; medium confidence)

- **AI use cases in practice:**
    - Inline code completion and chat in the IDE with GitHub Copilot. A Zoominfo rollout to more than 400 developers measured acceptance rates (33% of suggestions, 20% of lines of code) and satisfaction. [1]
    - Developers self-reported a median 20% reduction in task time, with 77% saying work quality improved. These are survey results, not measured output. [1]
    - A randomized controlled trial at Accenture used DevOps telemetry plus a survey and found high adoption and satisfaction. The 'up to 55% faster' figure comes from GitHub's earlier lab studies, which the same post cites, not from the Accenture trial. This is vendor-run research. [2]
    - Generating unit tests, debugging and documenting code in the IDE with Gemini Code Assist, which cites sources when it quotes at length. [3]
    - Agentic coding in the terminal or IDE with Claude Code, using checkpoints to rewind changes. Subagents and hooks are described as Agent SDK support for custom workflows. [4]
    - Code review support: Zoominfo flagged limits in domain-specific context and the need to vet generated code. [1]
- **Capstone deliverable:** Refactor or document one real module (non-production data) using an approved assistant. Deliver the merged pull request, a prompt log, the tests that gate it, a security review of the AI-generated diff, and a measured before-and-after time comparison against a similar manual task. Assessed against a rubric on correctness, test evidence and honest reporting of rework.
- **Data risks and rules:** Source code, credentials and API keys, proprietary algorithms and customer data in test fixtures. Rules: no secrets or production data in prompts; use enterprise-licensed tools with data-retention terms checked; review licence and citation flags on suggestions; treat generated code as untrusted until tested and scanned. Regulatory hooks (GDPR for personal data in fixtures) apply but were not covered by sources.
- **Adoption KPIs:** Weekly active users as a share of licences; suggestion acceptance rate; pull request cycle time against a pre-rollout baseline; developer satisfaction survey score; defect or revert rate on AI-assisted changes.
- **Curriculum emphasis:** Core tier, so most hours go to hands-on practice, then a short module on risk. Prioritise GitHub Copilot (the most evidence of enterprise rollout), Claude Code (agentic multi-file work with verification) and Gemini Code Assist (a Google Cloud shop). Spend a block on verification habits: run tests, review diffs, never accept blindly.
- **Tool-list fit:** Good fit overall. Gemini Code Assist's own documentation says new Standard and Enterprise subscriptions are no longer available for purchase, so confirm availability before teaching it. [3] Cursor is listed but no opened page covers it: not verified. ChatGPT Enterprise is a general assistant and is a weaker fit for IDE work than the others (not verified).

**42 Quality Engineering & Testing** (Advanced; medium confidence)

- **AI use cases in practice:**
    - Test case design and requirements refinement with an LLM assistant; the World Quality Report 2025 says these now lead GenAI adoption in quality engineering [1].
    - Generating first-draft Playwright or Selenium specs from a prompt, user story or recording; reviewers must make each test fail before trusting it [2].
    - Self-healing locators that repair selectors when markup changes; each heal should be reviewed, as it can hide a regression [2].
    - Failure triage that turns a wall of failed tests into a probable cause [2].
    - Test selection and flake detection to decide what to run and what to trust; keep a scheduled full run as a backstop [2].
    - Defect analysis and reporting, the earlier GenAI use now being overtaken by input-side work such as test design [1].
- **Capstone deliverable:** Within about 12 hours: take one real user story, produce an AI-drafted Playwright suite of at least 10 tests, and show that each test fails against a deliberately broken build before it passes. Submit the prompt log, a review checklist covering hallucinated selectors and assertions, a heal-review record, and measured time versus manual authoring.
- **Data risks and rules:** Test environments often hold copies of production data, including personal data (GDPR), payment card data (PCI DSS) and health data (HIPAA). Rules: use synthetic or masked data in prompts, never paste credentials or proprietary source into unsanctioned tools, and keep a human reviewer for all generated tests. The WQR 2025 ranks data privacy (67%) and hallucination or reliability (60%) among the top barriers [1].
- **Adoption KPIs:** 1) Share of new tests drafted with AI and merged after review. 2) Test authoring time versus baseline (WQR reports an average 19% productivity gain, with one third seeing minimal gains [1]). 3) Flaky-test rate and failures triaged per engineer. 4) Escaped-defect rate for AI-assisted versus manual suites. 5) Healed locators reviewed within one sprint (%).
- **Curriculum emphasis:** Most hours on prompting for test design and on validating AI output (mutation and fail-first checks), because generated tests can be confidently wrong [2]. Prioritise Playwright (the execution target), GitHub Copilot or Claude Code (drafting and refactoring specs) and ChatGPT Enterprise (requirements refinement). Spend little time on self-healing until locator hygiene is covered; the source notes stable test ids fix the same brittleness permanently [2].
- **Tool-list fit:** The list fits well: Playwright is a framework rather than an AI tool, but it is the natural target for generated tests. Gemini Code Assist is a generic coding assistant with no testing-specific evidence found. Omitted: AI-native testing platforms such as OpenText, Tricentis and mabl. The WQR press release notes OpenText was recognised as a Leader in the 2025 Gartner Magic Quadrant for AI-Augmented Software Testing Tools [1]; Tricentis and mabl were not verified from an opened page. Note the WQR is co-published by OpenText, a vendor in this space.

**44 DevOps & Site Reliability Engineering** (Specialist; medium confidence)

- **AI use cases in practice:**
    - Autonomous alert investigation: Datadog Bits AI SRE analyses runbooks and telemetry, forms hypothetical root causes, validates its findings and delivers a conclusion to collaboration tools before on-call staff log in (vendor claim: hours to minutes). [1]

- **Data risks and rules:** Tickets and endpoint logs contain employee personal data (GDPR, employment law), credentials, device and network details, and sometimes regulated data. Rules: redact identifiers before prompting, use only enterprise-approved tools, and require human approval for irreversible autonomous actions. Gartner found 69% of organizations suspect or confirm prohibited public GenAI use (survey of 302 cybersecurity leaders) [2].
- **Adoption KPIs:** 1) True AI resolution rate (no recontact in 72 hours), not dashboard deflection; the source says true rates often run 15-25% below vendor dashboards [1]. 2) Mean time to resolve for AI-assisted tickets. 3) Knowledge articles created from tickets and share reviewed within SLA. 4) Stale article share in the knowledge base. 5) Employee CSAT after AI-handled contacts.

Prioritise ServiceNow Now Assist (ticket workflow), Microsoft 365 Copilot (documentation and communications), and Claude or Gemini (article drafting and troubleshooting analysis); these tool names are not covered by the cited sources. Microsoft Security Copilot is a weaker fit for routine end-user support, because it targets security operations (this is my judgement, not stated in an opened source). The list names no end-user device-management or non-ServiceNow ITSM AI tooling; I did not verify specific omitted products. Caveat: the main source is written by the CEO of a competing AI-native ITSM vendor (Ravenna), so its framing of vendors is not neutral.
