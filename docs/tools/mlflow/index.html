What it is

MLflow is an open-source AI engineering platform for agents, LLM applications and classic ML models. You self-host it or use a managed version (for example MLflow on Databricks). It provides a server, UI and SDKs.

Vendor and product family
Open source project (Linux Foundation affiliation not verified), originally created by Databricks. Managed versions are offered by Databricks and cloud providers.
Handbook category
Data, analytics & AI platforms

Key capabilities

  • Tracing and observability for agents and LLM apps
  • Evaluation with LLM-as-a-judge scorers and datasets
  • Prompt management and optimisation
  • AI Gateway for model access
  • Experiment tracking, model registry and deployment

Enterprise data handling

Not applicable as a vendor service when self-hosted: data stays in the organisation's own infrastructure, and security depends on the deployment. Role-based access control arrived in MLflow 3.13 and was extended in 3.17 (October 2026) to runs, traces, assessments, logged models, review queues and model, prompt, scorer and MCP-server versions, with a DENY permission. The managed version on Databricks falls under Databricks' platform terms, and no SOC 2, ISO 27001, HIPAA or FedRAMP claim was verified for MLflow itself.

Licensing and pricing

Free and open source under Apache 2.0, per mlflow.org. Costs are infrastructure and staff, or Databricks usage if managed.

Integrations

Any LLM provider, agent framework and ML library (per mlflow.org general positioning; specific integrations not itemised). Relevant to dept 51.

2025-2026 developments

MLflow 3.17.0 (6 October 2026) added extended resource permissions (RBAC with DENY), TypeSafe Jev judge models and faster trace analytics. The project reports over 30 million monthly downloads. RBAC with an Admin UI first shipped in 3.13.

Best-fit handbook departments

51 AI, Machine Learning & Automation is the only listed department and the fit is strong for evaluation, tracing and MLOps governance.

Listed for these departments in the handbook

51 AI, Machine Learning & Automation

Training notes

Learners need experiment and trace logging, designing evaluation datasets and judges, registry versioning, and access control. Suggested 20-30 hours.

Caveats

Self-hosting needs operations effort. Features move quickly between releases. LLM-as-a-judge scores need human calibration.
