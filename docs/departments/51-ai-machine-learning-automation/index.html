AI use cases in practice

  • Evaluate LLM apps and agents with evaluation datasets, judges and scorers in MLflow [1]
  • Trace agents in production (tracing, regression testing and CI/CD supported) [1]
  • Collect human feedback in MLflow [1]
  • Build agents on Microsoft Foundry (formerly Azure AI Foundry) with built-in tracing and enterprise-readiness capabilities [2]
  • Govern agents with Entra identity, RBAC, content filters, network isolation and Azure Policy [2]
  • Apply configurable safeguards to generative AI apps with Amazon Bedrock Guardrails [3]

Capstone deliverable

Build and evaluate one RAG or agent prototype: evaluation dataset, scorers, a regression run, guardrail configuration and a governance note mapped to the NIST Generative AI Profile. Include documented prompts and time saved against hand testing.

Data risks and rules

Training and retrieval data may include personal, confidential or licensed content (GDPR, copyright; not verified in sources). Rules: control which data enters RAG indexes, apply access controls on agents [2], use guardrails [3], keep evaluation traces free of personal data, and document risk per NIST AI RMF [4].

Adoption KPIs

Share of AI apps with an evaluation set; regression failures caught before release; agents with owner and access review; guardrail-blocked incidents; time from prototype to approved release.

Curriculum emphasis

Prioritise MLflow (evaluation discipline), Microsoft Foundry and Amazon Bedrock (platform governance and guardrails), and Claude Code for building. Teach evaluation-driven development first.

Tool-list fit

Strong fit overall. Google AI Studio is not verified in an opened source and suits prototyping more than governed production. Choose Foundry or Bedrock according to cloud. Not verified: Vertex AI or Databricks Mosaic as omissions.
